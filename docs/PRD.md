# 마이링크 (MyLink) 제품 요구사항 정의서 (PRD)

## 1. 프로젝트 개요
* **프로젝트명**: 마이링크 (MyLink)
* **목적**: 크리에이터와 개인이 흩어져 있는 자신만의 다양한 링크를 하나의 페이지로 모아 효과적으로 퍼스널 브랜딩을 할 수 있도록 돕는 멀티 링크 프로필 서비스.
* **대상 사용자**: 
  * 여러 소통 채널(포트폴리오, SNS, 유튜브 등)을 하나의 링크로 묶어 관리하고 공유하고 싶은 크리에이터, 인플루언서 및 일반 사용자 전반.

## 2. 기술 스택 및 데이터베이스 구조 방향
* **디자인 시스템**: `shadcn/ui` 기반 모던 컴포넌트 사용 (테마 커스텀 기능 미지원)
* **인증 시스템**: Firebase Authentication (구글 소셜 로그인 전용)
* **데이터베이스**: Firebase Firestore
  * **핵심 모델링 설계 원칙**: 사용자 문서에 `displayName`(활동명/닉네임) 필드뿐만 아니라 **`username`(실제 사용자의 이름)** 필드도 반드시 함께 포함되어야 합니다. 각 유저가 소유하는 링크 데이터는 유저 문서 하위의 **서브 컬렉션(Sub-collection)** 구조를 사용하여 관리합니다.

## 3. 핵심 기능 목록 (초기 구현 범위)

- [ ] **구글 소셜 로그인 연동** (단일 인증 방식)
- [ ] **디스플레이네임 기반 URL 설정** (구글 Gmail 이메일 앞부분을 디스플레이네임 초깃값으로 사용)
- [ ] **인라인 편집 프로필 관리** (연필 힌트 아이콘을 통해 `username`(실제 이름), `displayName`(닉네임/슬러그), 소개글을 인라인 수정)
- [ ] **개별 링크 클릭 통계** (자신의 퍼블릭 페이지 내 각 링크별 누적 클릭 조회수 표시)
- [ ] **자동 파비콘 연동** (구글 파비콘 API 사용)
- [ ] **링크 블록 관리** (링크 생성, 연필 아이콘을 통한 인라인 수정, 삭제)
- [ ] **퍼블릭 프로필 페이지 노출** (자신의 URL로 접근 시 방문자에게 보여지는 모바일/웹 반응형 화면)

## 4. 각 기능의 상세 설명

### 4.1 로그인 및 URL 시스템
* **구글 소셜 로그인**
  * Firebase Auth를 기반으로 오직 구글 계정을 이용해 간편하게 로그인합니다.
* **URL 슬러그와 디스플레이네임(`displayName`) 결합**
  * 사용자의 활동명에 해당하는 **`displayName`** 값이 곧바로 퍼블릭 접속 URL의 슬러그(Slug) 역할을 수행합니다. (예: `mylink.com/[displayName]`)
  * 초기에 부여될 `displayName` 값은 복잡함을 줄이기 위해 로그인 처리에 사용된 **구글 지메일 아이디의 앞부분(@ 앞부분)**을 추출하여 자동으로 설정합니다.
  * *(예시: `hello1234@gmail.com`으로 로그인한 경우, 기본 `displayName`은 `hello1234`가 되며, 이로 인해 본인의 접속 URL 역시 `mylink.com/hello1234`로 맵핑됩니다. 기존에 논의한 난수 부여는 제외됩니다.)*

### 4.2 인라인 편집(Inline Edit) 기반의 프로필 관리 시스템
* **이름의 이원화 및 이미지 업로드 규칙**
  * 별도의 프로필 이미지 업로드 기능은 삭제되었으며 구글 소셜 계정의 기본 아바타 사진을 그대로 사용합니다.
  * 사용자를 식별하는 텍스트로써, 공개적인 활동명이자 URL 슬러그로 맞물릴 **`displayName`(디스플레이네임)** 영역과, 구글 계정이나 사용자 본연의 아이덴티티를 나타내는 **`username`(실제 이름)** 영역을 분리하여 각자 역할에 맞게 화면에 보여줍니다.
* **프로필 텍스트 인라인 수정**
  * 대시보드 화면상에서 실제 이름(`username`), 닉네임(`displayName`), 짧은 소개글 세 개의 항목을 별도 창으로 이동하지 않고 그 자리에서 바로 변경하는 **인라인 편집(Inline Edit)** 방식으로 동작합니다.
  * 텍스트 영역 옆에 **작은 연필(Pencil) 아이콘** 등 시각적인 힌트를 직관적으로 두어, 클릭 시 즉각 수정 모드로 전환되도록 디자인합니다.
  * *(참조: `displayName`을 사용자가 인라인 편집으로 수정하면, 본인의 URL 슬러그 구조도 그에 맞추어 함께 변경됩니다. 변경 시 중복 검증 로직은 개발 단에서 함께 처리합니다.)*

### 4.3 링크 관리 및 파비콘 시스템
* **새로운 링크의 추가**
  * 이동할 '대상 URL'과 버튼에 적힐 '제목 텍스트' 입력을 통해 링크를 생성합니다. (링크 순서 변경, On/Off 기능 등 제외)
* **링크 항목 인라인 수정 및 삭제**
  * 만들어진 개별 링크 버튼에서도 제목이나 URL 부분 옆의 **연필 아이콘**을 누르면 즉시 입력창으로 바뀌어 수정할 수 있는 일관된 **인라인 편집** 경험을 제공합니다.
  * 불필요한 특정 링크 항목은 완전 삭제가 가능합니다.
* **구글 API 기반의 파비콘(Favicon) 연동**
  * 사용자가 입력한 URL의 도메인(호스트명)을 분석해, **구글 파비콘 API** (`https://s2.googleusercontent.com/s2/favicons?domain=...`)를 호출하고 버튼의 좌측 아이콘으로 자동 시각화합니다.

### 4.4 개별 링크 조회수 (통계)
* **링크별 누적 클릭 통계**
  * 대시보드 화면상에서 자신이 생성한 각각의 링크 버튼들이 방문자에 의해 실제로 몇 번 클릭되었는지 그 횟수(조회수)를 직관적으로 텍스트로 표시합니다. 
  * (전체 페이지 단순 방문자 수 카진트는 제외하고, 실질적 액션이 통계되는 개별 링크 클릭수만 중점적으로 추적하여 보여줍니다.)
